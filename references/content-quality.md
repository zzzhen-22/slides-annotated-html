# 讲解内容质量标准（套件唯一不能自动化的部分）

> `run_all.py` 能把**机械部分**全部做完（骨架、渲染、组装、体检、截图）。
> 它做不了的只有一件事：**逐页读懂课件，写出讲解**。
> 这份文档就是那一件事的验收标准 —— 换个课件时，照它写。
>
> 流水线跑完后 `probe_doc.js` 会报 `内容进度：待补页面 N / M`。
> **N 降到 0、且 TODO 注释清零，才算交付。**

---

## 一、动手前：先建立"这一页在讲什么"的判断

### 1. 必须逐页看图，不许只看文字层

```bash
PY="$(command -v python || command -v python3)"
SK="<套件目录>"          # 即 pdf-slides-annotated-html 所在目录
"$PY" "$SK/scripts/prepare_pdf.py" "<课件.pdf>" "_extract" 860 75
```

产出 `_extract/page-01.png … page-NN.png`。**用 Read 工具逐张看一遍**，
再动笔写任何一页。

**为什么不能只看 `_extract/raw.txt`**：PPT 导出的 PDF 里数学符号用的是嵌入子集字体，
ToUnicode 映射常常是坏的。实测（清华 AI 导论课件）：

| 文字层里 | 真实含义 | | 文字层里 | 真实含义 |
|---|---|---|---|---|
| `¡` | 减号 `−` | | `¼` | `π` |
| `®` | `\mathbf{w}` | | `Ã` | `\sigma` |
| `2` | `\in` | | `¤` | `*` |

**同一个坏码位在不同文件里含义还不一样**，所以换课件必须重新核对，不能沿用上表。

拿不准的符号用高分片局部放大单独看：

```python
page.get_pixmap(dpi=400, clip=pymupdf.Rect(x0, y0, x1, y1))
```

实在判不出来就用**语义反推**交叉验证：`exp(¡ ®v)` 里的 `¡` 在 Sigmoid 公式里必然是减号，
因为 \(\frac{1}{1+\exp(+v)}\) 不可能把实数压进 (0,1)。

### 2. 每页先定一个"这页在干什么"

一句话。写不出来说明还没看懂 —— 回去再看图，别硬写。
这句话会成为该页讲解的第一句。

## 二、单页讲解的五段结构

每页（`<section class="pg" id="pNN" data-page="N">` 里的 `.pg-text`）按这个顺序写：

1. **这页在干什么**（1–2 句，结论前置）
   > 这一页在解决上一页留下的问题：当某个取值从未出现时，概率估计会变成 0。

2. **正文要点**（把 slide 上的字讲成人话，不是抄）
   公式用 `<script type="math/tex">` 写，中文注释用 `<span class="gloss">（…）</span>` 挂在公式后。

3. **补原文跳过的推导** → 放 `.note`（蓝）
   > 这一步怎么来的？把上式两边取对数就得到 —— 原文省略了中间这步。

4. **指出原稿的问题** → 放 `.flag`（红），如实标注，不静默改
   > 原稿这里的求和下标写成了 `i=1`，按上下文应为 `i=0`；下文推导用的是 `i=0`。

5. **与前后页的伏笔/回收**（显式点出来）
   > 这个式子是第 47 页要证的核心引理的一半。

**四种提示框的语义（别混用）**：

| 类 | 颜色 | 用途 |
|---|---|---|
| `.tip` | 绿 | 直觉、类比、正面提示 |
| `.note` | 蓝 | 补充说明、被跳过的推导（**本文档新增的解释一律放这里或 `.tip`**） |
| `.flag` | 红 | 警告、原稿有问题 |
| `.quote` | 灰 | 原文引用 |

## 三、结构性要求（每份产物都要有）

| 位置 | 内容 | 谁生成 |
|---|---|---|
| `00_intro.html` | 封面、使用说明、全文脉络表、前置知识（`.primer` 折叠卡） | 骨架自动，**脉络表后半段与 primer 要人工写** |
| `<段>0_ovN.html` | 每个大节一张「本节概述」卡 | 骨架自动，**三句话定位 + 核心问题 + 读完应能要人工写** |
| `<段><片>_pXX_pYY.html` | 逐页讲解 | 骨架自动，**全部要人工写** |
| `90_outro.html` | 一页纸速查表 + 术语表 + 关于 | 骨架自动，**速查表与术语表要人工写** |

### 「本节概述」卡怎么写

三部分，别写成目录复述：

- **`<p class="lead">`**：三句话说明**这一节的地位**、它解决什么问题、与前后节怎么衔接。
- **`核心问题`**：这一节要回答的 1–3 个问题（不是知识点罗列）。
- **`读完应能`**：可检验的能力（「能自己推导出 X」而不是「了解 X」）。

### 收尾的速查表与术语表是复习价值最高的两块，别省

速查表每行：公式/概念 ｜ 一句话含义 ｜ 出处页码（`<a href="#pNN">P12</a>`）。
术语表每行：中文 ｜ English ｜ 一句话解释。

## 四、交付前的自检清单

跑 `run_all.py --skip-init --skip-prepare`，然后逐条确认：

- [ ] `probe_doc.js` 的 **`内容进度：待补页面 0 / N`**
- [ ] **`TODO 注释残留 0 处`**
- [ ] `probe_doc.js` 的 `抽屉里的「P？」残留 0 处`
- [ ] `check_math.js` 的 `⑧ 正文缺字体检（组合符号 U+20D0–U+20FF）` 为 `0 处 ✔`
- [ ] `probe_doc.js` 的 `正文缺字风险` 与 `非法命名实体` 均为 `0 处 ✔`
- [ ] `check_math.js`：公式语法失败 0、含 CJK 0、标签全部平衡、目录缺失锚点 0
- [ ] `check_ui.py`：`ALL PASS`
- [ ] `probe_marks.js`：`RESULT: PASS`
- [ ] `逐页区块 / 缩略图 / 深链` 三者数量一致
- [ ] **人工抽查 3 页**：截图里的公式与 `page-NN.png` 逐一对照，确认没讲错

最后一条不能省 —— 自动化只能验结构，**讲错了内容它验不出来**。

## 五、反面清单（这几种写法都算不合格）

| 写法 | 为什么不合格 |
|---|---|
| 把 slide 上的字原样抄一遍 | 那是复制，不是讲解。读者自己会读 slide |
| 每页都写「本页介绍了…」开头 | 没有信息量，且暴露没看懂这页的作用 |
| 公式直接贴文字层抽出的坏码位 | 必然讲错（`¡` 当成了感叹号之类） |
| 原稿明显有问题却假装没看见 | 讲解者的价值就在这。如实标注在 `.flag` 里 |
| 把中文塞进 `\text{}` | KaTeX 字体没有 CJK，会走兜底字体导致字距错乱 |
| 分片里写 `<footer>` | 外壳模板已统一生成页脚，会出现两个 |
| 自己手写缩略图 `<figure class="thumb">` | `build.py` 会自动注入，手写会重复 |
| 正文里用组合箭头 U+20D7 表示矢量（`J` + U+20D7） | **中文字体栈没有这个字形，会渲染成方框（tofu）**。改写成 `<em><b class="vec">J</b></em>` 加粗表示；`config.json` 的目录标签同理 |
| 用 `&oiint;` `&iint;` 这类非 HTML5 命名实体 | 它们只存在于 MathML/LaTeX，浏览器不解码，会原样显示成「&oiint;」这串字面文本。直接写字符 `∯` `∬` 或放进公式 |
