# 踩坑清单（PDF/PPT 课件 → 对照式 HTML）

> **给 agent 用的快查手册**：按「做课件的生命周期 + 对象」分组，组内按「最易踩、最致命、最静默失败」排前。
> 每条固定三段 —— **症状**（怎么认出来）／**根因**（为什么）／**处理**（具体怎么做）。
> 动手写正文前先扫 C 组（公式/标签）和 F 组（标记）；动脚本前先看 A 组。

---

## A. 开工前：需求、结构与文档规范

### 1. 开工前先问清需求，再动任何脚本

**症状**：漏问「单文件还是多文件」等关键需求，做完返工。
**根因**：约束性条款写在中后部，被更靠前、语气更强的「第一步就是跑脚本」覆盖。
**处理**：需求确认（单文件/多文件、原文件跳转方式、纯图页处理、大纲与正文不一致）前置为「第 0 步」硬闸门，用 `AskUserQuestion` 一次问完；在「先跑脚本」处留回指锚点。

### 2. 结构在「读内容」之前定，而不是之后

**症状**：分段与页标题在读懂内容前就被焊死，回头改要连带改 shards/锚点/概述卡，成本高到没人愿改。
**根因**：`init_project.py` 在读内容前就按「每 8 页一切」「文字层首个合格行」定死结构；而 PPT 导出的 PDF 文字层顺序 ≠ 视觉阅读顺序，公式框常压在标题上方。
**处理**：先跑 `plan_outline.py` 巡读结构信号（书签/编号/封面清单）出 outline 草案，人工确认后再 `--outline` 建骨架。

### 3. 单文件还是多文件，先问

**症状**：做完发现体积超标。
**根因**：单文件会把 KaTeX、缩略图（可选还有 PDF）全内嵌，几十页轻松到 10–20 MB。
**处理**：开工前问清；在意体积走多文件（`index.html` + `katex/` + `img/`），共享性更好。

### 4. `--force` 重建骨架会覆盖已写好的讲解

**症状**：重建后几万字讲解瞬间回到 TODO 骨架，没有撤销键。
**根因**：`--force` 覆盖不检查目标文件是否已含实际内容，「重建骨架」与「重写内容」共用同一开关。
**处理**：重建前先把 `content/` 与 `config.json` 备份到项目外；按 `id=pNN`（页码是稳定键）逐页抽回旧讲解填回新分片。

### 5. 页数 < 切段粒度时，fallback 产生重复分段

**症状**：outline 草案里同一批页同时出现在两个 section，建骨架时被覆盖性校验拦下。
**根因**：fallback 用「循环起点 0 + `continue` 跳过首页」，`n_pages ≤ size` 时 sections 为空，随后的「补齐未编号页」逻辑退化成 head/tail 重叠。
**处理**：fallback 用 `while` 从第 2 页起切；「跳过首页」直接把起点设 1，别用 continue。小参数边界要靠最小用例（真实样本测不出来）。

### 6. 面向读者的说明别塞实现细节

**症状**：读者吐槽「太啰嗦、别写特定浏览器」。
**根因**：把「写给维护者的技术背景」和「写给读者的操作说明」混写在同一处。
**处理**：读者只留「怎么用」；技术背景（如选区迷你菜单的三条入口理由）放源码注释与 SKILL 维护者小节。

## B. 读 PDF：文字层不可信（错了会讲错知识点）

### 7. 别只靠 `get_text()` 抽文字就动笔

**症状**：数学符号的字体映射常是坏的（`¡`=减号、`¼`=π、`®`=w），照文字层写必然讲错公式。
**根因**：PPT 导出的 PDF 文字层是字体映射产物，不是语义文本。
**处理**：逐页看图（`_extract/page-NN.png`），文字层只当参考，不要只读 `raw.txt`。

### 8. 课件里的公式可能不严谨

**症状**：原文公式本身有笔误或记号不精确。
**处理**：照抄原文，在讲解里加注提醒，**不擅自「修正」**——宁可标注「此处原文如此」。

### 9. 大纲与正文可能不一致

**症状**：目录/大纲说的与正文实际内容对不上。
**处理**：以正文为准，不一致处加注说明。

### 10. 给人看的字符串先归一化

**症状**：目录里「同一个字看起来不是同一个字」、标题变成公式片段（`F(x, y, y′) =`）、段名页码重复（`（P1–P8）（P1–P8）`）。
**根因**：① PDF 文字层汉字可能是康熙部首码位（U+2E80–U+2FDF），字体回退按码位走；② 标题抓「首个长度≥2 的非空行」撞上浮在标题上方的公式框；③ 段名兜底分支和调用方各拼了一次页码。
**处理**：凡显示给用户的字符串先 **NFKC 归一化 + 空白/标点规整**；跳过「以运算符/等号结尾、无中文且短」的行当标题；页码只在调用方拼一次。

## C. 写公式与标签：KaTeX / HTML

### 11. `type` 属性笔误 → KaTeX 静默不渲染

**症状**：公式以源码形式残留，`probe_doc` 报「未渲染的 script 残留」，但**无任何报错**。
**根因**：`site.js` 用 `script[type^="math/tex"]` 前缀匹配，`type="math\tex"`（反斜杠）或 `type="math"`（漏 `/tex`）都匹配不上，被跳过。
**处理**：统一写 `type="math/tex"`（行内）或 `type="math/tex; mode=display"`（独立）；写完扫一遍有没有 `math\` 反斜杠。

### 12. 中文 / 全角符号别进公式

**症状**：公式里的中文渲染成空白。
**根因**：KaTeX 无 CJK 字形；**全角括号（（））也算 CJK**，`\text{（Gram matrix）}` 这种最容易漏（人工只查汉字）。
**处理**：中文注释放公式外 `<span class="gloss">`，公式内只用半角 ASCII；`check_math.js` 的 CJK 检测会兜底。

### 13. KaTeX 里 `#` 是宏参数符

**症状**：`# of samples` 报 `parse error: got '#'`。
**处理**：写 `\#`，或改成 "number of"。

### 14. 用 `<script type="math/tex">` 承载 LaTeX，实体一律裸字符

**好处**：script 内容按原始文本解析，反斜杠、花括号、`<`、`>` 都不用转义，只有 `</script` 会截断（LaTeX 里不可能出现）。
**反面**：HTML 实体**不被解码**——写 `&gt;`/`&lt;`，KaTeX 收到字面 `&gt;` 报错。公式里 `<`、`>`、`&` 一律写裸字符，实体只出现在普通 HTML 文本里。

### 15. 别用 `<script>` 当占位标签；高亮只用 `mark.hl`

**症状**：正文整段凭空消失；高亮退化成浏览器默认黄色甚至无样式。
**根因**：浏览器见 `<script>`（不管 type/class）就按脚本解析、吞内容直到下一个 `</script>`；`hl-blue`/`hl-red` 这类类名根本没在 CSS 里定义。
**处理**：非公式的占位/强调用普通 `<b>`/`<div>`；高亮用 `<mark class="hl">`，动手前 `grep` 一遍 `site.css`/`site.extra.css` 确认类名存在。

### 16. 正文矢量别用组合箭头 U+20D7

**症状**：公式（KaTeX）里矢量正常，正文里全是方框。
**根因**：U+20D7 属「符号用组合附加记号」区块，中文字体栈普遍无此字形；KaTeX 在自己的字体里画 `\vec`，所以「公式正常、正文方框」是这个 bug 的指纹。
**处理**：正文矢量统一写 `<b class="vec">J</b>`（`.vec{font-weight:700;font-style:inherit}`）；`check_math.js` ⑧ 已做硬性体检（挖掉 math 区块后统计 U+20D0–U+20FF，>0 即失败）。

### 17. 公式批量自检必做

**症状**：几百条公式里混着个别坏公式，肉眼绝对发现不了。
**处理**：`check_math.js` 一次跑语法 / CJK / 标签配对 / 目录锚点 / 缩略图数量；新增体检项记得同步 `run_all.py` 的 `parse_check_math` 白名单。

## D. 构建与体积

### 18. HTML 注释里的字面标签会骗过构建

**症状**：缩略图「在」但 DOM 里查不到；标签配对报 `open=6 close=12`。
**根因**：注释里写了字面 `</section>`，非贪婪 `.*?` 撞上它提前收尾，缩略图被插进注释内部、真收尾标签变游离。
**处理**：注释里不写任何字面 `<xxx>`；脚本「先匹配整段再改写」前**先把注释挖走再匹配**（`build.py`/`init_project.py`/`check_math.js` 三处已加固）。

### 19. woff2 之外的字体格式删掉

**症状**：KaTeX 字体 1.2 MB，内嵌 base64 膨胀到 1.6 MB。
**处理**：每条 `src:` 裁到只剩 `.woff2`（20 个合计 296 KB，base64 后约 400 KB）；`katex_offline.py` 已内置。

### 20. 缩略图分辨率先算体积再定

**处理**：**860–900 px / quality 75**（占满屏放大公式仍可读，63 页约 2.5 MB）；600 px 以下放大后糊。

### 21. 页脚会重复

**症状**：页面底部两个页脚。
**根因**：外壳模板一份、正文最后一个分片又一份。
**处理**：正文分片只放 `<section>`，页脚交给 `shell.html`；验 `html.count('class="doc-foot"')==1`。

### 22. 原文件深链的可迁移性

**症状**：默认 `file:///D:/.../slides.pdf#page=N` 是绝对路径，换设备失效。
**处理**：`embed_pdf: true` 内嵌 base64（`<script type="text/plain" id="pdfB64">`）→ 点击惰性解码成 `blob:` URL 打开并拼 `#page=N`，加「另存原 PDF」按钮；体积 ×1.34。**深链是锦上添花，缩略图才是保底**（部分浏览器限制 `file://` 跳转）。

## E. 无头截图与体检（验证手段）

### 23. 探针结果写「字面标签」；截图 harness 别滚动

**症状**：probe 报「没拿到结果」；截图是一张纯背景空图（8 KB）。
**根因**：① `createElement` 造的 `<pre id="__r">` 序列化后 `id` 与 `>` 间多了属性，`rfind('<pre id="__r">')` 字面串匹配不上；② 无头截图下 `scrollIntoView`/`scrollTo` 会把视口送出内容区。
**处理**：回传结果一律 `document.body.innerHTML = '<pre id="__r">' + esc(...) + '</pre>'`；截图 harness **完全去掉滚动**，换目标就换 `--section` 重截，别靠滚。

### 24. 自检「看起来卡死」其实是全程静默

**症状**：自检 1–2 分钟无任何输出，观感与卡死无异，真卡住也看不出卡在哪步。
**根因**：`subprocess.run(capture_output=True)` 跑完才打印。
**处理**：改 `Popen` + 逐行实时透传（子进程加 `-u`）；加两级看门狗（无新输出 120 s 告警、总时长 900 s kill）。长任务用工具自带的 `run_in_background`，别用 shell 的 `&`。

### 25. 无头截图 `#fragment` 不生效

**症状**：`... "file:///x.html#p52"` 截到的永远是页面顶部。
**处理**：注入 `<style>` 把其它区块 `display:none` 让目标排最前；`shot.py --section p52` 已封装。

### 26. Edge 首次运行隐私弹窗污染截图

**症状**：截到「微软重视您的隐私」。
**处理**：加 `--user-data-dir=<临时目录> --no-first-run --no-default-browser-check`；`shot.py` 每次 `tempfile.mkdtemp()` 并清理。

### 27. URL 必须三个斜杠

**症状**：白屏或 404。
**处理**：`file:///D:/path/x.html`；用 `urllib.parse.quote(path, safe='/:')`（**safe 里保留冒号**）。

### 28. 无头虚拟时间下 transition / smooth 不推进

**症状**：抽屉/侧栏停在动画开始前（坐标超出 viewport），`scrollIntoView` 后 `top` 仍是几万像素。
**根因**：`--virtual-time-budget` 快进定时器但不推进 CSS 过渡/平滑滚动——**是测试假象，不是产品 bug**。
**处理**：测试脚本先禁用：`.drawer,.toc,.selbar{transition:none!important} html{scroll-behavior:auto!important}`；「量出来的坐标离谱」先怀疑动画被按住，别急着改产品代码。

### 29. 8.3 短路径下 Chromium 静默失败 / 「退出码 0 + 0 字节」的三种成因

**症状**：截图/探针命令退出码 0、无 stdout/stderr、不生成文件。
**根因**（2026-10-15 补正，此前只记了第一种，另外两种更常见）：
  ① `tempfile.gettempdir()` 在部分 Windows 环境返回 `SHENYU~1` 短名，Chromium 不接受。
  ② **去提权**（**最常见**）：Chromium 启动时若认为进程处在「提升的完整性级别」（某些宿主进程/沙箱会给出这种令牌），会**派生一个去提权的子进程、父进程立刻退出**。`subprocess.run` 抓到的是那个马上退场的父进程，渲染结果留在子进程里、句柄已跟丢。加 `--enable-logging=stderr --v=1` 才看得到真因：
     `VERBOSE1:base\win\elevation_util.cc RunDeElevated: Started process, PID: …` / `Histogram: Windows.AutoDeElevateResult`。
  ③ 浏览器本体在该模式下不可用（实测 Edge 在 headless 下**两者皆不可用**）。
**处理**：① `long_path()` 用 `GetLongPathNameW` 展开；profile 别放项目盘。② **一律附带 `--do-not-de-elevate`**（`kitpath.browser_flags()` 已封装，`shot.py`/`probe.py` 自动带上）——实测 Chrome + 该参数立刻恢复输出。③ 若加了参数仍「0 字节 + 退出码 0」，**换 Chrome**：`set KIT_BROWSER=<Chrome 绝对路径>`（用户级安装常在 `%LOCALAPPDATA%\Google\Chrome\Application\chrome.exe`，`browser_exe()` 已把它纳入探测）。**不要**反复重试、**不要** `taskkill msedge`（用户自己的浏览器也是同名进程）。**通用教训**：「退出码 0 + 无输出」不是「程序没跑」，很可能是「跑在了另一个进程里」——先加 `--enable-logging` 看进程模型，别急着怀疑页面或参数。

## F. 交互：标记与笔记（最容易改坏结构）

### 30. 跨元素上色会把 DOM 结构搬坏

**症状**：标记处凭空多换行、被标内容不再高亮、跨格划线让表格散架。
**根因**：`surroundContents` 跨元素时抛错，旧代码退回 `extractContents` 把被「部分包含」的块级元素**克隆进 `<mark>`**（行内元素塞了块级子元素）。
**处理**：只对「文字节点内部的一段」动手，**永不搬动元素**——按块级祖先分组、组内二分收敛到单节点；**禁用 extractContents 兜底**（宁可一条笔记拆多个 mark）。判定指标是 `audit()` 的 `blockInsideMark`。

### 31. 重开页面标记全失效：文本空间不同源

**症状**：标记时正常，重开后抽屉挂黄框、正文无高亮（跨格/含公式的笔记尤其）。
**根因**：① `Selection.toString()` 在块级边界插 `\n`、单元格边界插 `\t`，而定位用 `TreeWalker` 拼接**不带分隔符**；② KaTeX 以 `htmlAndMathml` 输出，同一公式在 DOM 里有 2–3 份，隐藏副本也算进文本。
**处理**：`projOf()` 建「可见文本投影」（跳过 `.katex-mathml`/`annotation`/`script`），**存与找都走它**；`locate()` 分层匹配（压缩空白→去空白）+ 命中后自愈改写回规范形式。

### 32. 「定位失效」误报：先 render 后上色

**症状**：笔记卡片常挂黄框「定位失效」，正文里却有高亮。
**根因**：`Notes.add()` 先 `render()` 卡片，上色 `wrapRange()` 却在其后，卡片生成那一刻 DOM 里没有 mark → 判 stale，且之后不重绘。
**处理**：`wrapRange()` 之后**无条件再 `Notes.render()` 一次**。警惕「测试入口和真实入口走不同路径」的假绿——验收要复现真实入口（鼠标选字→点工具条按钮）。

### 33. 零宽字符产生「宽度 0 的 mark」

**症状**：`zeroWidth=2`，肉眼完全看不出（mark 包住的是零宽字符）。
**根因**：KaTeX 渲染 `\frac` 时插入真实 U+200B，而 `/^\s*$/` 的 `\s` 不匹配它。
**处理**：`isBlankStr()` 把 U+200B–U+200F、U+202A–U+202E、U+2060、U+FEFF 并入空白，**存（canon）与找（candidates）两端同改**，否则旧记录带零宽会落到兜底层。

### 34. `file://` 下所有本地页面共享同一 localStorage 域

**症状**：A 文档里做的标记出现在 B 文档。
**根因**：`file://` 是不透明源，Chromium 把本地页面归到同一存储域。
**处理**：`build.py` 按文档注入 `DOC_NS = 'lr-doc:' + md5(title + '|' + 配置里的 out)[:10] + ':'`，`site.js` 所有 key 拼在 NS 前；种子用配置里的 `out`（不是 `--out` 覆盖值），否则试构建和正式构建串成两份。

### 35. 脚本取词标记别取到 KaTeX 的 MathML

**症状**：造测试标记时抽屉显示 LaTeX 源码。
**根因**：KaTeX 同时产出可见 `.katex-html` 与隐藏 `.katex-mathml`，脚本按「第一个够长文本节点」取词会取到后者。
**处理**：`projOf()` 统一跳过 `.katex-mathml`/`annotation`，取词与定位共用一套投影；测试脚本取词同样跳过。

### 36. 网页压不住浏览器的「选区迷你菜单」

**症状**：自绘「标记」浮层被系统菜单盖住、点不到（`z-index` 多高都没用，那菜单是浏览器 UI 层）。
**处理**：三管齐下——① 浮层放选区**下方**避让（`useBelow`，`r.bottom+12`）；② 顶栏常驻 `#markBtn` + 快捷键 `M` 兜底（点按钮前 `mousedown→preventDefault` 保住选区，配 `lastSel` 缓存）；③ 有选区时接管右键弹自绘菜单，**必须补「复制」**并留 `Shift+右键` 放行系统菜单。

### 37. 重叠的标记会嵌套（正常，别当 bug 修）

**症状**：`audit()` 里 `nested: true`，DOM 出现 `<mark><mark>…</mark></mark>`。
**根因**：`wrapRange` 只跳过「同一条笔记」已标片段，不同笔记重叠按嵌套处理。
**处理**：保留（直接跳过所有已标片段会让新笔记一个 mark 都建不出、立刻「定位失效」）；`unwrap()` 先移子节点再删自身，嵌套安全。**要盯的是 `blockInsideMark`，不是 `nested`。**

### 38. 没有页码的区块显示「P?」甚至标不了

**症状**：概述卡/封面/速查表上划词，位置徽标显示 `P?`；无 id 卡片点「标记」只弹「标记不了」。
**根因**：徽标写 `'P'+(m.page||'?')` 而概述卡无 `data-page`；`markSelection` 用 `closest('section[data-page], section[id]')` 找不到无 id 卡片的宿主。
**处理**：`locOf()` 按 `data-page`→`ov-kicker`+`ov-range`→`h2/h3`→`#id` 兜底；`ensureSectionIds()` boot 时给无 id 的 section 补 `sec-<n>`（文档静态、编号稳定）。

### 39. 标记探针在「骨架期 / 纯图课件」上会自灭

**症状**：`probe_marks.js` 输出 `cases:[]` + `FATAL`，退出码却 0，上游判不出「其实没测」。
**根因**：四个用例要从 `.pg-text` 现找「相邻段落/≥3 列表格/段内加粗」，骨架期/纯图课件凑不齐。
**处理**：用例集为空时探针**自造**一组（两段文字 + 3 列表格 + 加粗）并纳入指纹基准。凡是「探针依赖被测文档恰好长成某样」都是隐患——让它自给自足。

## G. 目录、环境与迁移

### 40. 目录长章节下半段永远滚不出来

**症状**：滚动条动、内容几乎不动，比视口高的章节下半段看不到。
**根因**：旧版扁平目录遗留 `.toc-group{position:sticky}`，改两级嵌套后 `.toc-group` 变成包住整章的容器，被整体钉住。
**处理**：`.toc-group` 改 `position:static`，真正要粘性的只有一级表头 `.toc-nav>.toc-group>.toc-head{position:sticky}`；`check_ui.py` ⑦ 已加回归断言。

### 41. 套件写死本机路径 → 整体打包迁移后全废

**症状**：换机器/用户名后找不到 node、浏览器；第三方包 `ModuleNotFoundError`。
**根因**：代码与文档写死 node 版本号目录（会随运行时升级变）、`C:\Program Files`、用户名路径；脚本顶部直接 `import pymupdf`。
**处理**：收口到 `scripts/kitpath.py`——探测顺序「环境变量 → PATH → 常见位置」，托管运行时目录**列目录 + 版本号倒序**；`require_deps()` 拦缺包并给出包名 + pip 命令 + 当前解释器路径。改后把套件拷到新目录改名跑 `selftest.py` 验证。

### 42. 覆盖技能资产前先看 mtime

**症状**：并行会话改过的 `site.css`/`build.py` 被按「记忆中的旧版本」重写，改动丢失。
**处理**：动技能文件前 `find <技能目录> -type f -printf '%TY-%Tm-%Td %TH:%TM %s %P\n' | sort`；改动后**拿旧产物做回归 diff**，别凭感觉说「应该没变」。

## H. 文档与口径

### 43. 加了功能只改「离代码最近的那份文档」→ 同一仓库里N 份文档互相矛盾

**症状**：README 开头写「五类交互」，往下翻到校验表又写「四类交互的接线是否完好」；英文 README 还停在「Four interactions」，压根不知道有字号这个功能。陌生人读到自相矛盾的两段，第一反应不是「哪里写错了」，而是「这项目不可靠」。
**根因**：**文档口径散在 6 个文件里，没有单一真源**。同一句事实（几类交互、流水线几步、校验哪几项）分别抄在 `README.md`、`README.en.md`、`SKILL.md`、`docs/workflow.md`、`scripts/run_all.py` docstring、`scripts/check_ui.py` docstring——加功能时改了离代码最近的那份（check_ui 的 docstring），其余五份靠人记。实测一次漂移就是 6 处。
**处理**：别再靠人记。① 挑**离实现最近、必然先改**的那份做真源——本项目是 `check_ui.py` docstring 里的「检查五项交互」；② 写 `scripts/check_docs.py` 从真源**派生**数字，断言其余文档与它一致；③ 新增文件必须同步进 README 目录树（`check_docs.py` ⑥ 组会查漏列）。**教训是「写完代码再想文档」这个顺序本身有缺陷**——口径类事实应该在设计时就指定唯一出处，其余位置引用它。

## I. 体检脚本自身的失效

### 44. 把「一种合法配置」当成缺陷来断言 → 体检永远报 FAIL，久了就没人看它

**症状**：`check_ui.py` 与 `probe_doc.js` 在**不提供原 PDF** 的文档上必然报 FAIL，尽管其它检查全绿。本仓库的在线 demo 就是这一类——原始课件因版权不入库，产物里根本没有可跳的原文件。当时的判断是「demo 固有设计，不修」，**判断错了**：受影响的不是 demo，而是**所有选择不内嵌原文件、且原文件不可得的文档**。
**根因**：两层。① `build.py` 的第三种形态没处理——`config` 没给 `pdf` 时，正则两个分支都不命中，模板里的 `<a class="pdf-link" data-page="N">` **原样留下**，成了没有 `href` 的悬空链接（点了没反应）。demo 是靠手工把它改成 `<span aria-disabled>` 才「解决」的，等于把缺陷藏起来。② 体检断言取的是**「有没有 `file:///`」这种单一形态**，没意识到「活链 / 停用态」是两种都合法的形态。更隐蔽的是 `check_ui.py` 用 `html.count('class="pdf-link"')` **字符串计数**——把 `<a>` 和 `<span>` 混在一起算，数字对上了，于是「深链数一致」PASS，**掩盖了「一个是死链一个是活链」这个本质差别**。
**处理**：① `build.py` 补第三个分支：无 `pdf` 时主动降级成 `<span class="pdf-link" aria-disabled="true" title="…">`，把「本来就没有原文件可跳」变成明示，不再留悬空链接；② `check_ui.py` 按形态分别断言（检测到停用态就查停用态是否做干净、是否残留悬空 `<a>`；否则才要求 `file:///`），数量检查改为**按标签分别数活链与停用态**并断言两者不并存；③ `probe_doc.js` 的 `a.pdf-link` 放宽为 `.pdf-link`，并把「只有停用态」单列为合法形态输出。**更普适的教训**：断言不能问「是不是我期望的样子」，要问「**是不是我无法接受的样子**」——前者遇到未覆盖的合法形态就误报，后者天然容纳新形态。

### 45. 用脚本按行号搬移源码块 → 文件头被吞，损坏难以察觉

**症状**：想给 `check_ui.py` 的输出分组重新排序，写了个临时脚本按「组起始行号区间」切割再拼接。结果文件第一行直接变成 `    print('=== ⑤ …')`——**docstring、`import`、`def main():` 全部消失**，缩进错误。
**根因**：切割区间从「第一个 `print('=== …`」开始，那个位置**已经在 `main()` 函数体内部**，脚本把函数头当成了「第一个组之前的内容」丢在重建范围之外。而 ⑦ 那组的区间一直延伸到文件尾（含最后的「数量一致性」收尾与 `sys.exit`），搬它就把收尾代码一起搬走了。
**处理**：`git checkout <file>` 一次性还原（**这类事故的第一反应就是回退，不要试图手工补**），改用 Edit 工具做精确替换。**两条硬规则**：① 搬移前先 `ast.parse()` 校验生成结果，**不通过就不落盘**——这条救了第二次尝试（第二次脚本已加前置校验，语法错时文件没被写坏）；② 临时脚本用完立刻删，别留在仓库里。**更根本的判断**：发现「顺序乱」时，先问值不值得动——本例 ⑧⑨ 是历史上插在 ⑤ 之后的老组，重新编号会让文档里「⑤ 之后是 ⑥」的说法失效，**收益远小于风险，最终只调整了 ⑩ 的位置、保留原编号**。

### 46. 体检脚本「挖内嵌载荷」挖得不全 → 二进制里的巧合被当成源码残留

**症状**：`check_math.js` ⑤b 报「TODO 残留 2 处」，流水线在 ④ 硬失败；可 `grep -n TODO` 全文只命中两行，而它们都是 `<figure class="thumb"><img src="data:image/jpeg;base64,…">`。肉眼翻那两行，是一眼望不到头的 base64，看不到任何 `TODO`。
**根因**：⑤b 为了避免误报，本来就会先挖掉内嵌载荷，但**只挖了 `<script>…</script>`**——因为历史上两次误报（内嵌 PDF 的 payload、探针源码注释）都藏在 script 里。缩略图的 `data:image/…;base64,…` 是**第三类**载荷，不在 script 里，于是漏网。而 base64 是随机字符序列，约每 2.4 万字节就有一次「恰好拼出 4 个可读字符」的期望——一份 82 页的课件里出现两次完全正常（2026-10-13 实测：`thumb_42.jpg` 与 `thumb_77.jpg` 同时命中）。
**处理**：① `check_math.js` 的挖掘从「只挖 script」改成「script + **所有 `data:<mime>;base64,…`**」——base64 是二进制载荷，本来就不该参与任何源码层体检；② 已经生成好的产物不必重跑流水线：用 PIL 把命中那两张缩略图**换一档质量重编码**（画面无损、字节序列全变），⑤b 立刻归零，2026-10-13 实测 quality=92 一次命中。**更普适的教训**：「为了防误报而挖掉噪声」时，**要把噪声的**类别**想全，而不是把它出现过的位置想全**——按位置枚举（script 里）迟早会漏掉新位置（img 里）；按类别（一切 base64 载荷）写才不会。

### 47. 课程层的「找元素找链接」没过剥离合成的样式表 → CSS 注释里的用法示例被当成真实链接

**症状**：`course_check.py` 的 ④ 组（跨讲 `.xref` 外链可达）在一门**还没写任何跨讲卡**的课上直接报 FAIL，指着一个谁都没写过的路径 `../…/x.html#p09`。可产物里 `grep -c 'class="xref"'` 只有 1 处，翻出来是 CSS 注释里的**写法示例**。
**根因**：`assets/site.extra.css` 的注释里带着 `.xref` 的完整用法示范（含一个字面 `<div class="xref">` 与假 href）。v2 的课程层检查在**正文标记**上找 `.xref` 卡——只挖了 HTML 注释与 `<script>`，**没挖 `<style>`**，那段示例就活了。同族的还有 `course_index.py` 的「文档里出现属性字样但没抽到」探测：骨架产物的注释里到处是 `data-concepts` 字样，用 `if 'data-concepts' in html` 会误报「属性可能挂错了位置」。
**处理**：在 `coursekit.py` 加公共助手 `body_html(html)`，一刀挖掉 `<script>` / `<style>` / HTML 注释三者，所有「在页面里找元素、找链接」的检查统一走它（`course_check.py` 的 `.xref` 与链接扫描、`course_index.py` 的声明探测）。**不要**拿它做正文抽取——正文抽取要把 `<script type="math/tex">` 变成〔公式〕占位符，用途不同（走 `html_text`）。**教训与第 46 条同源但场景更近**：噪声类别里「样式表里的用法示例」是独立的一类，因为它长得**就像真实标记**——按位置枚举（只挖注释、只挖 script）永远会漏。

### 48. 新样例没铺开就断言 → 体检「ALL PASS」其实什么都没查

**症状**：把课程层体检接进 `selftest.py` 后全绿，看着很稳。但翻它的体检输出，统计行写的是「0 个术语 ｜ 0 条要点」，④ 组写着「本课程还没有 .xref 跨讲卡」——③④⑤⑥ **四组一条真断言都没执行**，PASS 只是「脚本没崩」。
**根因**：`selftest.py` 造的合成 PDF 没有内容作者，产物里的 `data-concepts` / 要点 / 术语全在**模板自带的 TODO 注释里**（剥离后为 0）。用它当课程样例，课程层的检查全部落在空集合上——**这正是第 44 条的病**：断言通过只说明「没有我无法接受的东西」，不代表「我真的看过东西」。
**处理**：三层。① 让样例**铺开**：`selftest.py` 的课程路线显式给它补上 v2 声明（三个 `data-*`、三条要点、两行术语、一张 `.xref` 卡），并断言统计行四个数**都 > 0**——把「没查东西」变成硬失败；② 断言「铺开」之后还要断言「查到了」：`.xref` 组要输出「检查了 N 条外链」且 N > 0；③ **反向注入**：把一条 `.xref` 指向坏锚点，重跑体检，**必须**报 `FAILED` 且能指名 `#p88`——没有这一步，前面的 ALL PASS 只证明脚本能跑。**推广**：任何「接进 selftest 的新检查」都要配一条「空转守卫」（断言对象非空）+ 一条「反向注入」（故意破坏必须被抓）。只有 ALL PASS 的绿色是不够的。

### 49. 内联 JS 的注释里写字面闭合标签 → 整页脚本被提前闭合（生成期全绿）

**症状**：课程主页公式显示成占位符〔公式〕，体检报「可见正文里有〔公式〕占位符」；同时 `script` 起止标签数**差 1**（58 开 / 57 闭）。最刺眼的是：故障点行号指向一段**注释**。
**根因**：给 `assets/course.js` 加公式渲染功能时，注释里为说明「公式标签长什么样」写了字面的起止标签。这段注释随后被 `course_site.py` 原样内联进 `<script>…</script>`，于是：① **HTML 解析器把注释里的闭合标签当成 script 元素的结尾**，后面全部代码降级成页面文本 —— 整页交互报废，而 Python 侧生成、静态链接检查、单讲体检**全部 PASS**；② 同一个字符串还让 `body_html()` 里「挖 script」的非贪婪正则 `/<script[\s\S]*?<\/script>/` 从**假标签**起算，配对整体错位，挖不干净，于是把 `course.js` 的源码文本当成「可见正文」、报出 1 处占位符。
**处理**：三层。① 把那处注释改写成不含字面标签的表述（`course.js` 的「⓪ KaTeX 渲染」段头已注明「故意不写字面起止标签」）；`course-shell.html` 里同样凑巧写了字面标签的注释一并改掉。② **生成期护栏**：`course_site._assert_no_script_end()` 扫待内联的 `.js`/`.css`，出现未转义闭合标签就 `SystemExit`（放行 `<\/script` 这类转义写法）。③ **成品自检**：`course_site.check_script_tags_balanced()` 数生成结果里的 `<script` 与 `</script`，不配对即报错 —— 资产级护栏只看文件，成品自检才是最后一道、也最接近真相的一道。**通用教训**：任何「把源文件原样嵌进另一种语法容器」的动作（JS 嵌进 HTML、JSON 嵌进 JS、模板嵌进模板）都要过一遍**容器级护栏**，且护栏要建在**可交付产物**上、不能只建在输入文件上 —— 截断也可能来自渲染函数拼串、shell 写错等别处。

### 50. 抽取器升级但缓存 key 只认输入哈希 → 新字段全空，而流水线全绿

**症状**：给要点/术语抽取器新增「保留公式」的富文本字段后，重跑 `course_index.py`，课程主页上的公式**依然**是占位符；`_course/keypoints.json` 里 `html` 字段确实有了，但术语表的 `def_html` 全是空。
**根因**：两层。① `course_index.py` 的增量缓存按**产物内容哈希**命中，只覆盖「输入变了」、不覆盖「算法变了」——抽取器升级后旧缓存被原样复用，新字段没机会生成。② 补了 `EXTRACTOR_VERSION` 之后，`build_glossary()` 汇总层仍在**只搬运 `zh`/`en`/`def` 三个纯文本字段**，新加的 `*_html` 富文本字段没跟着汇总上去，渲染端回退到转义纯文本，公式又变回占位符。两处都是「首页显示可疑，但生成与体检全绿」。
**处理**：① 缓存 key 升级为「产物哈希 **且** `EXTRACTOR_VERSION` 一致」，脚本顶部写明「改了 coursekit 抽取逻辑就 +1」；② 汇总层收集字段时**成对收集**（纯文本与其富文本版同源同序地 append），避免「`zh` 取自 L01、`zh_html` 取自 L03」的错配；③ 在 `course_check.py` 加两组静态断言兜住这类回归：「入口页内联了 KaTeX」与「可见正文里没有〔公式〕占位符」。**通用教训**：增量缓存至少要包含**算法版本**这一个维度，否则「改了算法却不生效」会伪装成「改动没写对」；而**派生字段（富文本版、规范化版、索引版）在每一层汇总/复制时都必须显式跟着走**——它们不会自动继承，漏一层就静默退化。
