## 〇、一句话目标

v1 解决「一份课件 → 一份逐页精解」。**v2 解决「一门课的 N 份精解 → 一个互相知道对方存在的整体」**：

1. **生成侧**：写第 N 讲的讲解时，能拿到「这门课至今已经讲过什么」，从而做出跨讲关联——不重复展开、术语统一、伏笔跨讲回收。
2. **组织侧**：把这门课的 N 份精解组成一个「课程合集」入口，可导航、可跨讲检索、可对照取用。
3. **提炼侧**：**在课程主页上自动长出一份「要点总结」**——每写完一讲它就多一块，无需人工维护第二份摘要。

## 一、v1 的现状与缺口（先把问题说准）

v1 的一个「讲次」就是一个自包含项目目录：

```
<某讲目录>/
├─ config.json          ← 讲次元数据（out/pdf/title/shards/groups/pages…）
├─ content/             ← 逐页讲解分片（人工写）
├─ _extract/            ← 逐页图 + 缩略图
├─ _katex/              ← 离线 KaTeX
├─ _plan/outline.json   ← 语义大纲（含 14 段的语义名、每页标题、confirmed 标记）
├─ README-项目.md
└─ <讲次名>-逐页精解.html   ← 单文件产物（内嵌 CSS/JS/KaTeX/缩略图/可选原 PDF）
```

**已经具备、v2 可以直接复用的资产**（这是本方案能做得轻的关键）：

| 资产 | 为什么 v2 能白拿 |
|---|---|
| `_plan/outline.json` | 每讲的**语义分段 + 每页标题**已经是结构化的。跨讲「讲了什么」不必重新解析正文。 |
| `config.json` 的 `pages` / `groups` | 讲次的页清单与目录结构，直接可做课程地图。 |
| 产物 HTML 的 `section.pg[id=pNN]` | 每页有稳定 id，跨讲深链直接用 `…#p51`。 |
| **`90_outro.html` 的 `#glossary` 术语表** | **列头固定为「术语｜English｜一句话解释」，且 `content-quality.md` 已把它列为必写项**——glossary 的三个字段可以零猜测地拿到（见 §3.3）。初稿漏了这个资产。 |
| **`90_outro.html` 的 `#cheatsheet` 速查表** | 同上，是「公式/概念｜含义｜出处」的结构化三列。 |
| v1 的正文搜索（`Find` 模块） | **v2 的跨讲检索是它的放大版**，索引结构可以复用同一套思路。 |
| `check_docs.py` 的「单一真源 + 派生断言」 | 课程层的术语与要点一致性检查照这个模式写即可。 |

**缺口**：

1. 讲次之间**零关联**。同一概念在两讲里可能用不同译名；同一段推导可能被讲两遍；前一讲留的伏笔（如「梯度消失后面再讲」）在后一讲不会被认领。
2. 写第 N 讲的 agent **读不到第 1…N-1 讲写了什么**——它只有当前这份 PDF 和页面图。
3. 没有任何东西知道「这门课一共有几讲、叫什么、哪讲讲什么」。
4. **没有任何东西把 N 讲的精华聚成一份可读的摘要**——想复习只能一份一份翻。

## 二、不可破坏的硬约束（先立规矩，再谈设计）

这四条来自 v1 的设计底线，**任何 v2 方案违反一条即否决**：

| # | 约束 | 理由 |
|---|---|---|
| C1 | **`file://` 直接打开、断网可用** | v1 全部价值的基础。**推论：不能 `fetch()` 同目录 JSON**——`file://` 是不透明源，本地 JSON 会被 CORS 拦死。因此任何「入口页 + 外部索引」的方案都必须把索引**内联**进 HTML。**再推论：不存在「不重跑脚本就自动刷新」的真·实时**——首页的数据只能来自构建期（见 §5.2）。 |
| C2 | **单讲目录可独立使用** | 别人可能只拿走第 3 讲。合集层只能是「在上面加一层」，不能要求讲次依赖课程目录才能打开。**推论：跨讲 `.xref` 链接在单讲被拷走时必然断链——必须让信息本体活在文字里，链接只是增强（见 §4.4）。** |
| C3 | **不做巨型合并单文件** | 一讲产物已 9–10 MB（含内嵌 PDF）。14 讲合并 ≈ 140 MB，浏览器直接崩；而且笔记的 localStorage 命名空间、内嵌 PDF blob 都会互相打架。 |
| C4 | **讲次目录名可迁移** | 所有跨讲引用用**相对路径**，不写绝对路径（v1 已有这条纪律，`check_docs.py` 有对应断言）。 |

## 三、目录与数据模型

课程 = 一个目录，讲次 = 它的子目录（v1 结构**原样不动**）：

```
<课程目录>/
├─ course.json               ← 课程级元数据（本方案新增，唯一真源）
├─ _course/                  ← 课程级派生物（全部可重建）
│   ├─ glossary.json         ← 术语权威表（从各讲 #glossary 抽，见 §3.3）
│   ├─ keypoints.json        ← 要点汇总（从各讲 #keypoints 抽，见 §3.4）
│   ├─ briefing-L07.md       ← 第 7 讲的「前序知识简报」（给 agent 读）
│   └─ index.json            ← 跨讲索引（由各讲产物派生，含上面两张表的缓存）
├─ lecture-01-why-dl/        ← v1 项目目录，结构不变
├─ lecture-02-cnn/           ← v1 项目目录，结构不变
└─ index.html                ← 课程合集入口（新产物，单文件、索引内联）
```

### 3.1 `course.json`（schema 定稿）

```json
{
  "schema": "course/v1",
  "name": "清华大学 · 深度学习",
  "instructor": "苏航（Hang Su）",
  "term": "2026 秋",
  "summary": "从「为什么需要深度」讲到 Transformer：先建立表示学习视角，再逐层拆开 CNN / RNN / 注意力。",
  "created": "2026-10-14",
  "lectures": [
    {
      "id": "L01",
      "dir": "lecture-01-why-dl",
      "title": "深度学习导论（一）：Why deep Learning?",
      "pdf": "3-Deep Learning-I.pdf",
      "page_count": 82,
      "status": "done",
      "done_pages": 82,
      "topics": ["why-dl", "feature-learning"],
      "outline": "lecture-01-why-dl/_plan/outline.json",
      "product": "lecture-01-why-dl/3-Deep Learning-I-逐页精解.html"
    }
  ],
  "unknowns": []
}
```

要点：

- **`dir` 是唯一键**，其它字段全部可由它派生（title 从 outline/config 抓，page_count 从 config 抓）。派生得出来的就不要手写——写两份必然漂移（这正是 v1 `check_docs.py` 要治的病）。所以 `course_init.py` 只让用户填**最少的东西**：课程名 + 讲次目录列表（+ 可选的 `summary` / `instructor` / `term`）。
- **`status` 四态**（初稿是三态，缺了「写了一半」——而骨架到写完之间往往是最长的一段）：

  | 状态 | 判据 |
  |---|---|
  | `pending` | 讲次目录不存在 |
  | `skeleton` | 目录在，但没有产物 HTML 或没有 `config.json` |
  | `partial` | 产物在，`0 < done_pages < page_count` |
  | `done` | `done_pages == page_count` |

  **全部由静态扫描判定，不手工维护、不依赖浏览器**（初稿说「由 `probe_doc.js` 自动判定」——`probe_doc.js` 是浏览器探针，14 讲就是 14 次 Chromium 启动，而 pitfalls 第 29 条记着浏览器会静默失灵。把课程地图这种基础信息押在最不稳的一环上不划算）。
- **`done_pages` 的静态判据**（与 `probe_doc.js` 同源，保证两者不会打架）：产物 HTML 里，`section.pg` 内部**不含**「待补」字样的 `.pg-text .note` 卡数量。`probe_doc.js:63` 用的就是这个判据。
- `topics` 是自由标签，用来在课程地图上做粗分类；真正的细粒度概念关系在 `glossary.json` 与各讲的 `data-concepts` 里。
- **讲次 id 是外键**（glossary / `index.json` / briefing 到处在引用它）。所以目录被改名时，`course_init.py` 走的是「已记录的 + 新扫到的」**合并**策略而不是纯扫描：纯扫描会让改名的那一讲换一个新 id、全身断链；合并则把它留成 `pending` 并告警，让人自己决定。
- **不写时间戳**：`created` 只在首建时写一次。带时间戳的派生文件每次重跑都会全文件变化，没法 diff。

### 3.2 `_course/keypoints.json`（要点汇总）

```json
{
  "schema": "keypoints/v1",
  "lectures": [
    {
      "id": "L01",
      "title": "深度学习导论（一）：Why deep Learning?",
      "status": "done",
      "hash": "a1b2c3d4",
      "points": [
        { "text": "深度网络的价值不在「更多参数」，而在「组合出的特征层级」。", "at": "p12", "topic": "feature-hierarchy" },
        { "text": "通用逼近定理说的是「存在性」，不是「可学性」——它不解释为什么梯度法能训起来。", "at": "p34" }
      ]
    }
  ]
}
```

- `points[]` 是**派生物**，真源在产物 HTML 的 `#keypoints` 卡里（§3.4）。
- `hash` 是产物 HTML 的内容哈希，用于**增量**：重跑 `course_index.py` 时哈希没变就复用缓存，不重抽（§5.2）。
- `at` / `topic` **可选**。缺 `at` 的要点只是不给出处深链，不算缺陷。

### 3.3 `_course/glossary.json`（术语权威表）

```json
{
  "schema": "glossary/v1",
  "terms": [
    {
      "id": "residual-connection",
      "zh": "残差连接",
      "en": "residual connection",
      "aliases": ["跳跃连接", "skip connection", "恒等捷径"],
      "def": "把输入直接加到子层输出上，使梯度有一条恒等通路。",
      "first": "L01:p58",
      "seen": ["L01:p58", "L01:p59", "L02:p12"],
      "conflicts": []
    }
  ]
}
```

**这是 A 侧能不能成立的关键**：

- 第 1 讲第一次出现某概念时，agent 在页面上写 `data-concepts="residual-connection"`；同时**在该讲 `90_outro.html` 的术语表里补一行**，并给这一行的 `<tr>` 加 `data-concept="residual-connection"`。
- **zh / en / def 三个字段直接从术语表那一行抽**——不猜、不抓标题、不留空。
  这是本版对初稿的修正：初稿说「zh/en 从页面的中英文标题或 `.gloss` 卡里抓，抓不到就留空待补」，
  但 `templates/content-skeleton/90_outro.html` 里**早就有**一张必写的术语表，
  列头就是「术语 ｜ English ｜ 一句话解释」，`references/content-quality.md` 第三章也把
  「速查表与术语表要人工写」列为结构性要求。**现成的结构化资产，不该再从标题里猜。**

  ```html
  <section class="card" id="glossary">
    <h2>术语速查表</h2>
    <table class="tbl gloss">
      <thead><tr><th>术语</th><th>English</th><th>一句话解释</th></tr></thead>
      <tbody>
        <tr data-concept="residual-connection">
          <td>残差连接</td><td>residual connection</td><td>把输入直接加到子层输出上…</td>
        </tr>
      </tbody>
    </table>
  </section>
  ```

  | | 初稿方案 | 本版方案 |
  |---|---|---|
  | 数据来源 | 页面标题 / `.gloss` 卡（格式不固定） | 强制存在、列结构固定的术语表 |
  | 退化路径 | 「抓不到就留空待补」——glossary 会变成半残表 | 无退化路径；术语表没写 = `content-quality.md` 本来就判不合格 |
  | 一致性检查 | 需额外定义「什么算同一 id 的 zh」 | 直接比对各讲术语表同 id 行的第一列，判定简单、不易误报 |

- 第 2 讲再遇到这个概念，`briefing` 会直接把 `zh` 给出，agent **必须沿用**（不许新造译名）；`course_check.py` 会扫后续所有讲，发现同一 `id` 被用了不同 `zh` 就报 FAIL。
- `aliases` 记录历史上用过的别的说法——不是纵容，而是**让检查能报出「这两讲说的其实是同一件事」**，从而提供合并建议。它是 glossary 里**唯一的手写字段**，`course_index.py` 每次重算时从上一版原样带过来。
- `first` / `seen` / `conflicts` 由 `course_index.py` 从各讲产物的 `data-concepts` 自动汇总，不手写：

  | 字段 | 含义 |
  |---|---|
  | `first` | 第一次出现的 `LNN:pNN` |
  | `seen` | 出现过的全部位置（按讲次顺序、页序） |
  | `conflicts` | 同一概念在各讲术语表里**说法不一致**时，把不同的值列在这里；非空即 `course_check.py` 判 FAIL |

### 3.4 `#keypoints` 卡（要点总结的真源）

**要点写在产物里，不另立 JSON 文件。** 这是刻意的取舍：

> **已否决**：把要点放 `_plan/keypoints.json`。理由有二 ——
> ① 引入**第二真源**：产物改了、JSON 没改，就会出现「首页有这条要点、产物里没有」的漂移，
> 而 §5.4 的抽取原则明写「只从产物抽」就是为了防这个；
> ② C2：单讲被单独拷走时，要点摘要会跟着 `_plan/` 一起丢，而它本该是这一讲的阅读成果。

在 `templates/content-skeleton/90_outro.html` 里新增一张卡（初稿没有这张卡，是本次增补）：

```html
<section class="card" id="keypoints">
  <h2>本讲要点</h2>
  <ol class="kpl">
    <li data-at="#p12" data-topic="feature-hierarchy">深度网络的价值不在「更多参数」，而在「组合出的特征层级」。</li>
    <li data-at="#p34">通用逼近定理说的是「存在性」，不是「可学性」。</li>
    <li>本讲的推导链条：单层线性 → 单隐层 → 逐层组合，每一步都在回答「为什么不是一层就够」。</li>
  </ol>
</section>
```

| 项 | 规则 |
|---|---|
| 容器 | 固定 `id="keypoints"`；抽取锚点就是它 |
| 条目 | 该容器内 `<ol class="kpl">` 的每个 `<li>` |
| 出处 | `<li>` 上可选 `data-at="#pNN"`，**必须指向本产物里真实存在的页 id** |
| 概念 | `<li>` 上可选 `data-topic="<glossary id>"`，把要点挂到概念上（术语总表与要点表互链） |
| 条数 | **建议 3–7 条**；超过 10 条 `course_index.py` 报 WARN、`course_check.py` 报 WARN（要点不是速查表，见 §5.8） |
| 写法 | 必须回答「这讲最值得记住的判断是什么」，**不是目录复述**（写法规范进 `content-quality.md`，见 §4.5） |

**为什么要点必须由 agent 显式写，而不能由脚本从速查表自动抽**：
速查表（`#cheatsheet`）是**公式级**的（一行一条公式），要点是**判断级**的（「为什么这行公式重要」）。
自动抽出来的会是一串公式名，不是要点；而且一旦「反正能自动抽」，agent 就不会认真写要点了。
两者是**不同抽象层的东西**，都应存在，但不互相替代（§5.8 有明确的分工说明）。

## 四、A 侧：内容层方法（生成新讲解时关联前序知识）

### 4.1 核心动作：写讲解前先拿一份 briefing

新增脚本：

```bash
python scripts/course_brief.py <课程目录> --for L07
# 默认写 <课程目录>/_course/briefing-L07.md；--out 可改路径
```

`briefing.md` 是**给 agent 读的**（不是给人看的），固定五节：

| 节 | 内容 | 数据来源 |
|---|---|---|
| ① 前序讲次地图 | 每讲的标题、页数、各语义段名 + 页码区间（一张表） | 各讲 `_plan/outline.json` |
| ② 术语权威表 | 已被前序讲次确立的 中/英/别名/首见位置 | `_course/glossary.json` |
| ③ 概念落点索引 | 「这个概念在前序哪讲的哪一页展开过」 | 各讲产物的 `data-concepts` 抽出的 `_course/index.json` |
| ④ 本讲大纲的**已讲预警** | 本讲每个语义段，若与前序讲次的某段标题相似度超阈值 → 「⚠ 前序已详述（L03 P12–P18），本讲应写『回顾一句 + 指路』而非重新展开」 | 本讲 `outline.json` × 前序 `outline.json`（标题 + 该段页标题的词面重合度） |
| ⑤ 待回收的伏笔 | 前序讲次里标了 `data-forward` 的开放问题，若与本讲大纲有交集 → 列出 | 各讲产物的 `data-forward` |
| 附 | 各讲产物的内容哈希 | 用来判断这份简报是否过期 |

**为什么用 markdown 而不是 JSON**：agent 读 markdown 更省 token、也更不容易误读结构；机器消费的部分（术语、索引用 JSON 另存 `_course/`）。

**段名里的页码只拼一次。** `outline.json` 的 `toc_label` 按约定已经是「N · 段名（P起–P止）」，
页码已经含在里面；简报展示时要自己拼一次，**比对时更要把页码剔掉**。这不是洁癖：
页码数字进了词袋，会让两段「页码区间相同但内容无关」的段落白得相似度。
（这是 pitfalls 第 10 条的原症状，实测重现了一次：修掉后噪声从 0.10 降到 0.057。）

### 4.2 内容层的三个新声明

在页区块上加三个 `data-*` 属性即可，不改渲染、不改 build 流程：

```html
<section class="pg" id="p58" data-page="58"
         data-concepts="residual-connection,degradation"
         data-pays-off="vanishing-gradients@L01:p77"
         data-forward="depth-vs-width">
```

| 属性 | 语义 | 谁用 |
|---|---|---|
| `data-concepts` | 本页**引入或重点讲解**的概念 id（对应 glossary） | 建 glossary、建概念索引、后续讲次的 briefing |
| `data-pays-off` | 本页**回收**了前序讲次的伏笔，格式 `概念id@讲次:页` | 生成「跨讲伏笔回收图」；反向可查「哪条伏笔还没人回收」 |
| `data-forward` | 本页**留下**的、后讲应当回收的开放问题 | 后续讲次 briefing 的第 ⑤ 节 |

### 4.3 三个属性的书写纪律（**本版收紧**）

初稿只说了「id 用小写连字符、不用中文」。不够——下面每一条都对应一种「流水线全绿但索引悄悄丢东西」的失败：

| 项 | 规则 | 谁验 |
|---|---|---|
| id 字符集 | `data-concepts` 逗号分隔；每个 id 必须匹配 `^[a-z0-9]+(-[a-z0-9]+)*$`；**不合法的 id 要 WARN，不许静默吞掉** | `course_index.py` |
| `data-pays-off` | 格式 `id@LNN:pNN`；**id 必须在 glossary 里存在**、**LNN 必须是 `course.json` 里真实存在的讲次**、pNN 必须 ≤ 该讲页数 | `course_index.py` WARN + `course_check.py` FAIL |
| `data-forward` | 单个概念 id，同字符集规则 | `course_check.py` |
| **位置** | **只能写在 `section.pg` 开标签上**，不得写进 `.pg-head` 或内层 `div` | 抽取是正则扫 section 开标签；写错位置 = 静默丢失 |
| **属性顺序** | **必须宽容**：`data-concepts` 放在 `data-page` 前面也要能抽到 | 见 §6.4，`build.py` 的正则必须一并放宽 |
| 可选性 | 三个属性**全部可选**。不写就不进课程索引，但不能让 build 失败——v1 的产物必须继续可用 | —— |
| 硬要求 | `data-page` / `id` 仍是硬要求（v1 已有），三个新属性是软要求 | —— |

> **「位置」这条最容易踩**：agent 手写时很自然会把 `data-concepts` 挂到 `<h3>` 上。
> 挂错了抽取脚本查不到 → 概念凭空消失，而**流水线全绿**。
> 所以 `course_index.py` 必须在「产物里出现了 `data-concepts` 字样、但一个 id 都没抽到」时**主动 WARN**，
> 而不是安静地少抽一条（pitfalls 第 44 条的教训：断言要问「是不是我无法接受的样子」）。

### 4.4 跨讲串联与 `.xref` 卡（含 C2 张力的处理）

v1 的「单页讲解五段结构」第 5 条是「与前后页的伏笔/回收」。v2 把它**拆成两格**：

5. **页内串联**（原有）：与本节前后页的伏笔/回收。
6. **跨讲串联**（新增，**有前序讲次时才写**）：
   - **前序已讲过** → 用 `.xref` 卡，给「第 3 讲 P14 已详述」+ **相对路径链接**；
   - **本讲首次引入** → 补 `data-concepts`，并在本讲 `#glossary` 术语表补一行（带 `data-concept`）；
   - **回收前序伏笔** → 补 `data-pays-off`，并在正文里显式写「这一页回答了第 1 讲 P77 留下的问题」。

新增卡片样式 `.xref`（灰蓝底 + **虚线**左竖线，与四类提示卡的实线区分）：

```html
<div class="xref"><b>跨讲：</b>第 1 讲 <a href="../lecture-01-why-dl/xxx-逐页精解.html#p77"
   title="需与课程目录一起拷贝才能跳转">P77</a> 曾把「梯度消失」留作伏笔，
   本页的残差连接正是它的答案。</div>
```

**C2 张力与处理**：`.xref` 的链接指向**别的**讲次目录，而 C2 允许「别人只拿走第 3 讲」——
那时这条链接必然断链。三条一起做，成本都很低：

1. **信息本体活在文字里**：「第 1 讲 P77 已详述残差连接」——链接只是增强，断链也不丢信息。
   这一条必须写进 `content-quality.md` 的 `.xref` 用法说明。
2. 给 `<a>` 加 `title="需与课程目录一起拷贝才能跳转"`，并在 `SKILL.md` 里明写这条取舍。
3. **验证现状（已实测，无需改 v1）**：`probe_doc.js` 的断链检查只扫 `section[id]` / `.toc-nav` 范围内的锚点；
   `check_math.js` ④ 只扫 `<nav>` 里的 `href="#…"`——**两者都不会把跨讲外链误报成断链**（好）。
   但 `course_check.py` 必须补一条**反向断言**：课程目录完整时，所有 `.xref` 外链必须可达。

**链接怎么写、要不要百分号编码**：手写时写**普通相对路径**即可（`../lecture-03-cnn/cnn-逐页精解.html#p09`），
中文字符现代浏览器能处理；**只有空格是真问题**（产物文件名取自 PDF 文件名，可能带空格），写成 `%20`。
`course_site.py` 自动生成的那些链接则一律走 `urllib.parse.quote(..., safe='/:')`（§5.5），
`course_check.py` 解析时先**解码再查**，两种写法都能过。

### 4.5 讲解模板的新增内容（写进 `content-quality.md` 与 `SKILL.md`）

`references/content-quality.md` 的改动清单：

1. 第二章「单页讲解的五段结构」→ **六段**（加「跨讲串联」）；
2. 新增 `.xref` 卡的用法（含 §4.4 的「信息本体在文字里」原则）；
3. 第三章结构性要求表里，`90_outro.html` 一行从「速查表 + 术语表 + 关于」改为
   「**本讲要点 + 速查表 + 术语表 + 关于**」，并说明术语表要加 `data-concept`、要点卡要加 `data-at`/`data-topic`；
4. 新增一节「**本讲要点怎么写**」：

   | 合格 | 不合格 |
   |---|---|
   | 「残差连接把输入直接加到子层输出上，为梯度提供恒等通路——这是深层网络可训的关键。」 | 「本讲介绍了残差连接。」（空话） |
   | 「通用逼近定理说的是存在性，不是可学性。」 | 「第 3 节讲了通用逼近定理。」（目录复述） |
   | 3–7 条，每条一个独立判断 | 20 条，把速查表抄了一遍（那是 `#cheatsheet` 的活儿） |

5. 第五章「反面清单」补 6 行：要点写成目录复述 / 要点抄速查表 / 要点超过 10 条 /
   `data-concepts` 挂错位置 / 跨讲链接只写「详见这里」。

### 4.6 待定的判断

- **相似度阈值先不拍板**。初稿建议「去掉停用词后 Jaccard ≥ 0.34」——方向（不上嵌入模型、走词面重合度）是对的，
  但 **0.34 这个数不该凭空定**：中文二字组的 Jaccard 分布与英文差别很大，拍歪了就会「要么全亮、要么全不亮」，
  那正是 pitfalls 第 44 条「体检永远 PASS 或 FAIL，久了没人看」的翻版。做法：
  1. `course_brief.py` **无论阈值多少都把 top-N 的分数原样打出来**（第 ④ 节附 `score=0.562`）；
  2. 在真实课程上人工看几条，**再**把阈值定死；
  3. 简报里明写「默认值只是占位，尚未校准」。**实测参考**：夹具上真预警 0.562、噪声 0.057，分得很开。
- 并且明确定义**预警是提示而非禁令**——写「⚠ 前序已详述（L03 P12–P18），建议『回顾一句 + 指路』」，
  不写「禁止展开」。否则 agent 遇到「本讲确实需要换角度重讲」时会不敢写。
- **briefing 不强制**。`init_project.py --course <dir>` 时**自动生成**并在终端提示「写讲解前先读它」。
  强制到「不读就报错」是做不到的（agent 行为不可控），所以靠提示 + `course_check.py` 事后审计。

### 5.1 新增产物：`index.html`（课程合集入口）

单文件、`file://` 可开、索引内联。**五个区块**：

| # | 区块 | 职责 |

> 之后可选加「记住上次停留的区块」（localStorage，**课程页自身**的 UI 状态、键名带
> `course:` 前缀防串），属阶段 4 的糖，不进核心 —— 它与 §5.10 的「学习进度」是两件事：
> 前者记「主页自己滚到哪」，后者读「各讲被读到哪」。

**跨讲跳转怎么带高亮**：给 v1 的 `site.js` 加一段「启动时读 `location.hash`」——
支持 `#p51`（滚到该页，v1 已由浏览器原生锚点支持）与新增的 `#q=<词>`（自动填入搜索框并 `Find.run`）。
合集里生成 `<a href="../L03/xxx.html#q=残差">`。
**实测确认这是纯新增**：当前 `site.js` 里**完全没有** `location.hash` / `hashchange` 的处理，
所以 `#q=` 不与任何既有逻辑冲突。这也是「先做搜索」排对了顺序的回报。

### 5.2 **要点总结页**（本版新增能力）

#### 它是什么

课程主页上的一个独立区块：**把每一讲的要点按讲次顺序拼成一张可读、可搜、可导出的总表**。
每写完一讲，它就多一块——不需要谁去维护第二份摘要。

#### 呈现形态

```
┌─ 要点总结 ─────────────────────────────────────────────┐
│ [课程目标] 从「为什么需要深度」讲到 Transformer：…        │   ← course.json.summary，可选
│ 过滤要点：[___________]        [导出 Markdown]          │
├────────────────────────────────────────────────────────┤
│ ▾ L01 · 深度学习导论（一）        82 页 · 已完成        │
│    1. 深度网络的价值不在「更多参数」，而在「组合出的特征层级」。 →P12  ⟡feature-hierarchy
│    2. 通用逼近定理说的是「存在性」，不是「可学性」。           →P34
│    3. …                                                │
│ ▸ L02 · CNN 基础（一）            76 页 · 部分完成      │   ← 默认展开，可收起
│ ▸ L03 · 深度学习导论（二）          — · 待建             │
│    （本讲尚无要点）                                     │
└────────────────────────────────────────────────────────┘
```

- **每讲可折叠**，默认全展开；`--- 页 · 状态 ---` 徽标与写作进度（未写完时的逐行标注）同源。
- **`→P12`** 是出处深链，指向该讲产物的 `#p12`；**`⟡feature-hierarchy`** 是 `data-topic` 生成的概念链接，
  点它跳到 ④ 术语总表里的那一条（把「要点」与「术语」两个视图缝起来）。
- **未写完的讲次显式占位**：`skeleton` / `partial` 状态显示「本讲尚无要点」或「还有 N 页未写完，要点待补」。
  **绝不静默省略**——空白会让人以为遗漏了，而「还没写」是必须一眼看出来的信息。
- **过滤框**：纯 DOM `indexOf` 过滤（要点文本已经内联在页面里，**不需要建索引**）。
  输入即过滤讲次块与条目，0 命中时显示「把过滤清空试试」而不是留一片空白。

#### 导出 Markdown

「导出 Markdown」按钮把当前（过滤后的）要点表落成一份 `.md`：

```markdown
# 清华大学 · 深度学习 — 要点总结

> 从「为什么需要深度」讲到 Transformer：…

## L01 · 深度学习导论（一）（82 页）

1. 深度网络的价值不在「更多参数」，而在「组合出的特征层级」。（P12）
2. 通用逼近定理说的是「存在性」，不是「可学性」。（P34）

## L02 · CNN 基础（一）※ 部分完成（53/76 页）

…
```

- 走 `Blob` + `a.download`，与 v1 `Notes.exportMd()` 同一套做法；
- **顶部自动附一行**「生成时间 + 覆盖讲次数 + 未完成讲次」，避免导出件被误当成完整版；
- 这是「要点总结页」最实用的出口（复习、打印、贴进笔记软件）。

#### 数据从哪来

`_course/keypoints.json`（§3.2）→ 内联进 `index.html`。真源是各讲的 `#keypoints` 卡（§3.4）。

#### 「每加一讲就实时更新」到底怎么实现（**把话说准**）

先把「实时」的可行边界讲清楚，避免承诺做不到的事：

> **做不到的**：不重跑任何脚本、打开首页就自动反映最新内容的「真·实时」。
> 因为 C1 要求 `file://` 断网可用，而 `file://` 是不透明源——首页**不能** `fetch()` 各讲产物，
> 一 fetch 就被 CORS 拦死。首页的数据只能来自**构建期内联**。
> 这是取舍，不是缺陷；§7 已把「`fetch` 外部 JSON」列进已否决方案。

**做得到、也就是本设计承诺的「实时」= 单一真源 + 幂等增量重建 + 一条命令收尾**：

| 机制 | 说明 |
|---|---|
| **单一真源** | 要点只写在产物 `#keypoints` 里（§3.4）。首页那份是**派生**的，所以永远不会「产物改了首页没改」。 |
| **增量** | `course_index.py` 按各讲产物的**内容哈希**判断是否需要重抽（§3.2 的 `hash`）。未变的讲次直接复用 `keypoints.json` / `glossary.json` 的缓存条目，不重新解析。14 讲规模下重跑是**毫秒级**（实测第二跑 0 重抽）。 |
| **一条命令收尾** | 新增/改完一讲后跑 `python scripts/run_course.py <课程目录> --sync`，一次完成 `index → site → check`。**这一步就是「每加一讲就更新」的全部操作**。 |
| **自动衔接** | `init_project.py --course <课程目录>` 建骨架时自动登记 + 出 briefing；`run_course.py --add <新讲目录>` 把「登记 → 出 briefing → 全量同步」一次做完。 |
| **未完成也可见** | 登记进 `course.json` 的讲次，哪怕还没写，也会在要点表里占一块显式占位（「本讲尚无要点」）。所以「加了一讲」这件事**当次同步就能在首页看到**，不必等写完。 |

→ 一句话：**写完一讲 → 跑一条命令 → 首页要点表多一块。** 这就是本设计定义的「实时」。

### 5.3 课程层的外壳与资源（**与单讲彻底分开**）

课程首页**不复用** `assets/shell.html`。理由：单讲外壳承载的是「左讲解右缩略图 + 标记笔记抽屉 + 字号调节」
那一整套，课程首页一样都用不上；强行复用会让两边的 CSS/JS 互相污染，
而单讲那套是被 `check_ui.py` + 4 个 `probe_*.js` 严格守着的资产，不该被无关逻辑侵入。

新增三个课程层资源：

| 文件 | 职责 |
|---|---|
| `assets/course-shell.html` | 课程页骨架（占位符由 `course_site.py` 替换） |
| `assets/course.css` | 课程页样式（五区块、要点表、徽标、过滤框） |

### 5.4 跨讲索引怎么生成

```bash
python scripts/course_index.py <课程目录>   # 扫各讲产物 → _course/index.json（+ glossary/keypoints）
python scripts/course_site.py  <课程目录>   # 把 index.json 内联进 index.html
```

**索引只从「产物 HTML」抽，不从 `content/` 抽。** 理由（初稿的判断正确，保留）：产物是最终交付物，
索引与它一致才有意义；从 `content/` 抽会出现「索引里有、产物里没有」（比如某分片没被加进 `config.shards`）。

抽取内容：每个 `section.pg` 的 `id / data-page / h3 文本 / 正文纯文本 / data-concepts / data-pays-off / data-forward`；
外加 `#glossary` 的 `tr[data-concept]`（三个字段）与 `#keypoints` 的 `li`。

抽取方式：**正则 + 轻量清洗**即可，不引入 HTML 解析库（保持 `requirements.txt` 只有 pymupdf + pillow）。
用 v1 里已有的字符归一化经验（NFKC、康熙部首、U+20D0–20FF 体检，见 pitfalls 第 10 / 16 条）。

**抽取正文时必须先挖掉三类东西**（顺序不能反，实测缺一不可）：

| 挖掉什么 | 不挖的后果 |
|---|---|
| HTML 注释 | 注释里大量出现字面标签与说明文字（pitfalls 第 18 条） |
| `<script>` | 公式源码与内嵌 PDF 载荷；公式保留成占位符 `〔公式〕`，把 LaTeX 塞进摘要既难读又占地方 |
| `<figure class="thumb">` | **缩略图 base64**——一份 82 页课件有 2.5 MB，不挖会让索引从 37 KB 涨到数 MB，检索结果里滚出一屏乱码 |

### 5.5 链接必须 URL 编码（**本版新增，实测依据**）

**依据**：`init_project.py:453` 的 `guess_meta()` 明写「文档名 = 产物文件名 / 品牌名，**一律取 PDF 文件名**」，
而真实课件文件名**普遍带空格**——本稿自己的示例就是 `3-Deep Learning-I.pdf` → `3-Deep Learning-I-逐页精解.html`。

**后果**：`href` 里出现裸空格时，浏览器行为不一致，`file://` 下**可能跳不过去**。
（中文字符现代浏览器能处理，**空格才是真问题**。）

**处理**：`course_site.py` 生成链接时统一走 `urllib.parse.quote(path, safe='/:')`
（v1 的 `build.py:223` 生成 `file://` 深链时已经在用这个 safe 集合），`#q=` 的值同样 `quote`。
**写进 `course_check.py` 的断言**：生成的 HTML 里，指向 `.html` 的 `href` 不得含**裸空格**；
解析链接时**先解码再查文件是否存在**，这样手写的普通相对路径（§4.4）也能过。

### 5.6 体积控制（必须做，否则入口页会到几十 MB）

| 模式 | 内联内容 | 14 讲估算 | 用途 |
|---|---|---|---|
| 默认 | 每页标题 + 每页**前 120 字** + 概念标签 + **要点全量** | 约 1–2 MB | 找得到、跳得过去；全文精确搜索留给各讲自己的搜索框 |
| `--full` | 每页全文 | 约 15–25 MB | 想在一个框里搜遍全课程时用 |

估算依据（本版补上，初稿只有结论）：不内嵌缩略图；1148 页 × 120 字 ≈ 0.4 MB 正文，
加标题、概念标签与 HTML 包装到 1–2 MB 合理。**要点全量内联的增量可忽略**（14 讲 × 5 条 × 60 字 ≈ 42 KB）。

两条硬要求：

1. **默认模式必须明说检索边界的限制**（入口页写一行提示），不能让用户以为「搜不到＝没有」——
   这是 v1 `probe_doc.js`「断言要问『是不是我无法接受的样子』」的同一条原则（pitfalls 第 44 条）。
   **具体要写明的两条**：只索引每页前 N 字；公式只留占位符、不参与检索。
2. **加自动降级保护**：`--max-text N`（默认 120）+ 产物超阈值（如 3 MB）时**自动降到 60 字**，
   并在**终端与入口页都明示**当前模式。体积这种指标不该只靠估算守住。

### 5.7 讲次改名 / 增删之后

`course.json` 里的 `dir` 是键。改目录名 → 必须重跑 `course_index.py` + `course_site.py`。
`course_check.py` 断言：

- `course.json` 里每个 `dir` 都存在，且其 `config.json` 可解析；
- `index.html` 里每条跨讲链接的目标文件真实存在、锚点（`#pNN`）在目标产物里真实存在；
- 每讲的 `#glossary` 里同一 concept id 的 `zh` 不漂移（`glossary.json` 的 `conflicts` 必须为空）；
- **`.xref` 外链可达**（§4.4）；
- **生成的 `href` 无裸空格**、解析时先解码（§5.5）；
- **`data-pays-off` 的 `id@LNN:pNN` 三段格式合法**且指向真实存在的位置（§4.3）；
- 各讲产物与 `index.json` 里记录的**内容哈希一致**（否则 briefing / 要点表可能过期）。

### 5.8 要点表 / 速查表 / 术语表的分工（别混）

三个表都在课程首页或产物里出现，容易做重。明确分工：

| 表 | 抽象层 | 粒度 | 位置 | 数量级 |
|---|---|---|---|---|
| `#keypoints` 要点 | **判断级**（「为什么重要」） | 每讲 3–7 条 | 产物 + 课程首页要点总结页 | 14 讲 ≈ 70 条 |
| `#cheatsheet` 速查 | **公式级**（「这个式子是什么」） | 每讲十几行 | 只在产物里 | 14 讲 ≈ 200 行 |
| `#glossary` 术语 | **词汇级**（「这个词什么意思」） | 每讲十几条 | 产物 + 课程首页术语总表 | 14 讲 ≈ 150 条 |

- 要点表**不并进**速查表，速查表也**不并进**要点表——混在一起会两头不讨好。
- 三者通过 `data-topic` / `data-concept` **互链**，而不是互相复制。
- `course_index.py` / `course_check.py` 报一条 WARN：某讲要点 > 10 条 → 「疑似在抄速查表」。

### 5.9 讲次返回入口（**可选注入**，2026-10-16 增补）

**问题**（审查 A6）：读者从课程主页点进一讲之后，只能靠浏览器后退回合集；
直接分享 / 新标签打开讲次的人更是回不去。而 C2 要求讲次必须能独立使用 ——
不能说「为了返回入口，让讲次依赖课程目录」。**「依赖」与「锦上添花的链接」是两回事**，
本节的方案就是把这两件事分开。

**设计：`config.json` 的可选字段 `course_home`**

```json
{ "out": "6-RL-强化学习-逐页精解.html", "course_home": "../index.html" }
```

- **值的语义**：课程主页**相对讲次产物所在目录**的路径（与 `.xref` 的解析基准一致）；
  由 `init_project.py --course` 在登记讲次时自动写入（跨盘符算不出相对路径时**不写 + 警告**，
  不猜）；config 里一律存正斜杠形态。
- **注入**：`build.py` 读该字段 —— 有值 → 在讲次顶栏最左注入
  `<a class="course-home" href="…">← 返回课程主页</a>`（href 统一 `quote`，§5.5 同款）；
  **没有该字段 → 一个字节都不碰顶栏**。
  响应式：**≤1024px 只留「←」箭头**（与 toc 抽屉化同断点）。2026-10-17：顶栏的
  「文档标题」已删（左上角目录顶部本就有品牌名，1025–1280 区间空间充裕，断点从
  1200 收回 1024——见 CHANGELOG「顶栏精简」）。**断点别选常用窗口宽度**——最早写的是
  `max-width:1280`，恰好罩住「1920 物理 @150% 缩放 = 1280 逻辑宽」这类常见配置
  （2026-10-16 实测报告，详见 CHANGELOG 未发布段的修复记录）。
- **为什么用「锚点插入」而不是占位符**：无痕天然成立（不注入 = 零接触，连空替换要
  小心空白的步骤都不需要），且「单讲 demo → 课程 demo 讲次副本」的注入与构建注入
  能共用**同一个函数**。锚点 `<div class="topbar">` 在组装完成的整页里必须**恰好出现 1 次**，
  不满足即硬失败（fail loud，pitfalls 第 44 条）。

**三条性质**（对 C2 红线的逐条回答）：

| 性质 | 落实方式 |
|---|---|
| **不默认** | 不声明字段 → 零注入；仓库 demo、selftest 默认产物都不含此元素 |
| **可选** | 删掉 config 字段重新构建即可移除；不需要任何 CLI 开关（声明一次、每次构建自动生效） |
| **不构成依赖** | 注入物只是一个 `<a>`：讲次的打开 / 目录 / 缩略图 / 笔记 / 搜索 / 公式全部不读课程目录。讲次被单独拷走时该链接失效（404），**其余功能毫发无损** |

**体检的落点**：`check_ui.py` ⑬ 组（条件式 —— 有链接查形态与位置，无链接 SKIP）；
`course_check.py` 对「各讲产物的 `.course-home` 链接」做**可达性**检查
（与 `.xref` 同一解析机制；没有链接的讲不查）。

**课程 demo 的演示**：`build_demo.py` 在「单讲 demo → 讲次副本」复制后调用
**同一个注入函数**（副本因此带上返回入口，课程 demo 形成「主页 → 讲次 → 主页」完整闭环）；
`--check` 断言 ① 相应升级为「副本 == 单讲 demo **经同一注入转换后**」（仍逐字节可校验）。

### 5.10 学习进度（**读取各讲阅读痕迹**，2026-10-17 增补）

#### 它是什么

课程主页的 ⑤ 区块显示**每讲的阅读位置与笔记数**（「上次读到 P42 · 5 条笔记 · 3 天前 · 继续」），
数据来自各讲产物写入**本浏览器 localStorage** 的阅读痕迹 —— 零网络、零上传、纯本机。

#### 数据链路（单一真源）

```
单讲 site.js（运行期写入）      lr-doc:<h10>:pos    {v,p,n,t}（本批新增）
                              lr-doc:<h10>:notes  （既有，标记笔记）
        │  file:// 同域共享（2026-10-17 实测：子目录写 → 根目录跨进程读，逐字节一致）
        ▼
course_site.py（生成期提取）   从产物 <var DOC_NS = "lr-doc:<h10>:"> 抓取 → cdata.lectures[].ns
        ▼
course.js（运行期读取）        按 ns 读 pos/notes → 渲染 ⑤
        ▼
course_check.py（静态复核）    cdata.ns == 产物 DOC_NS（不符即红，防改名后忘重建）
```

`ns` **从产物提取、不从 config 重算**：产物里的 `DOC_NS` 就是真源，提取 = 结构上不可漂移。

#### 三条性质

- **只读**：课程页对 localStorage **只读不写**（不改变「课程页无写入」的现状）；
  读取失败（隐私模式 / 清缓存 / 数据损坏）一律降级为空态，不报错、不影响其它区块。
- **单向**：讲次侧的 `pos` 写入**不读课程目录**（C2 不变）——讲次被单独拷走，
  写入照常、功能毫发无损，只是主页看不到它；反过来，主页少了任一讲的产物也只是少一行。
- **本机性**：数据只属于这台电脑的这个浏览器；换浏览器 / 换机器 / 清缓存 = 从零开始。
  讲次改名（title / out 变化 → ns 变化）等价于换命名空间，旧记录不再关联
  （与既有「笔记跟 ns」行为一致；course_check 的哈希 + ns 双重闸门保证改名必重建）。

#### 记录侧的克制（语义诚实）

`pos` 只记「**最后停留的页**」：不记已读页集合、不记滚动偏移、不记时长。
文案写「上次读到 P42」而非「已读 67%」—— 后者会假装知道用户没读过的页。
写入时机三条覆盖：换页时写（滚动节流）/ 页面隐藏时写 / `pagehide` 兜底。

#### 测试

`templates/probe_pos.js`（单讲：换页写 / 隐藏时强制写 / 无 `.pg` 区块时 SKIP）+
`probe_course.js` ⑭ 组（预置 keys → 三态渲染 / 总览 / href / 空态 / `pageshow` 重读）+
`course_check.py` 的 ns 一致性组 + 反向注入（ns 提取 / 渲染 / 换页写入三个变体）。

#### `build.py` 专项说明（**本条推翻了初稿的「预计零改动」**）

**实测结论：必须改。** `scripts/build.py:208`：

```python
masked, n_pg = re.subn(r'<section class="pg" id="p\d+" data-page="\d+">.*?</section>',
                       inject, masked, flags=re.S)
```

这条正则要求开标签**在 `data-page="N"` 之后立刻闭合**。实跑验证：

| 输入标签 | 旧正则 | 放宽后 |
|---|---|---|
| `<section class="pg" id="p58" data-page="58">`（v1 现状） | ✓ | ✓ |
| `<section class="pg" id="p58" data-page="58" data-concepts="…">`（本方案写法） | **✘ 失配** | ✓ |
| `<section class="pg" id="p58" data-concepts="…" data-page="58">`（属性换序） | **✘ 失配** | ✓ |

**后果**：只要按本方案加了任何一个 `data-*`，**缩略图一个都不会注入**——产物每页都缺原页图。

**修法（三步）**：

1. 正则放宽为「任意含 `class="pg"` 且含 `data-page` 的 section 开标签」，**不依赖属性顺序**：

   ```python
   RE_PG_TAG = re.compile(r'<section(?=[^>]*\bclass="pg")(?=[^>]*\bdata-page="\d+")[^>]*>')
   RE_PG_BLOCK = re.compile(RE_PG_TAG.pattern + r'.*?</section>', re.S)
   ```

   实跑逐例核对（Python 与 Node 两侧对齐 8/8）：v1 原样 ✓／属性追加在后 ✓／属性换序 ✓／
   class 不在最前 ✓／概述卡 ✘／无 data-page ✘／`class="pg-extra"` ✘／`class="pg-head"` ✘。

2. `inject()` 内部取页码的 `re.search(r'data-page="(\d+)"', block)` **不用改**（它本来就只找属性）。
3. **补硬断言**：注入数必须等于区块数（用同一个匹配式数），不等就 `raise SystemExit`。

   当前 build.py 只 `print('注入缩略图区块: %d')` 然后继续跑，一个数字不痛不痒。
   这是 pitfalls 第 44 条的正面应用：**别问「是不是我期望的样子」，要问「是不是我无法接受的样子」**。

> **⚠ 同源拷贝四处**：`build.py` / `coursekit.py` / `check_math.js` / `check_ui.py` 各有一份等价实现。
> **改一处就要改四处**，否则「缩略图 N / 逐页区块 M」会互相打架。
> （初稿与 附二 曾判断 `check_math.js` / `check_ui.py` 无需改动 —— 实测后**改了**：
> 它们的字面计数隐含要求 `class` 紧跟 `<section`，属性换序时会与 build.py 的注入数对不上，
> 而那会变成一条**误报**。体检误报比漏报更糟，见 pitfalls 第 44 条。）

## 七、已否决的方案（连同否决理由，避免下一任 agent 重新走一遍）

| 方案 | 否决理由 |

| **课程首页复用单讲的 `assets/shell.html`** | 单讲外壳承载「左讲解右缩略图 + 标记笔记抽屉 + 字号调节」，课程页一样用不上；硬复用会污染被 `check_ui.py` + 4 个探针严格守着的资产。**另起 `course-shell/course.css/course.js`。** |
| **课程层用 `probe_doc.js` 判讲次状态**（初稿写法） | 那是浏览器探针，14 讲 = 14 次 Chromium 启动，而 pitfalls 第 29 条记着浏览器会静默失灵。地基信息改**静态扫描**（§3.1）。 |
| 「讲次返回入口」按「**讲次依赖课程目录**」实现（默认注入、必需） | 违反 C2 的依赖红线。**但允许其「可选注入」形态**（2026-10-16 增补）：`config.course_home` 默认零注入、不构成依赖 —— 讲次的打开与全部功能都不读课程目录，注入的只是一个**可能失效的链接**（单独拷走时 404，其余毫发无损）。分界线是「**才能打开**」 vs 「**锦上添花**」，详见 §5.9。 |
